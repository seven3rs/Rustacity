Rustacity

Audio editing, forged in Rust.

The Audacity editor you already know — multi-track, sample-accurate, scriptable — with a memory-safe Rust audio core underneath and a sandboxed WebAssembly extension engine beside it.

Why this fork

Two things Audacity does not do — added underneath it.

Rustacity keeps the editor intact and changes what runs beneath it: new audio code is written in Rust, and third-party code runs in a sandbox instead of on your machine.

New audio code is Rust

Signal processing moves out of legacy C++ into the rustacity-dsp crate, behind a small C interface. It is tested on its own with cargo test and needs no C++ toolchain to work on.

  • Memory-safe DSP, ported unit by unit
  • Every ported routine checked against reference values captured from the original C++

Extensions run in a sandbox

A WebAssembly host lets people add functionality Audacity does not have, without handing third-party code the keys to the machine. An extension gets audio blocks and one logging call — nothing else.

  • No filesystem, no network, no environment access
  • A fault inside an extension stops that one call, not the editor

A careful port

A port is not finished until the old C++ is deleted. Reference values are captured while the original still exists, so behavior — quirks included — is reproduced, not guessed.

  • Goldens live in rust/dsp/goldens/reference.txt
  • Progress is tracked in docs/port-status.md

Nothing is taken away

The existing plug-in system — VST, LV2, AU, Nyquist — is left exactly as it was. The extension engine is built alongside it, not as a replacement for it.

  • Everything Audacity 2.4.1 does, it still does
  • Contributions stay GPL v2 compatible
How it fits together

Two halves joined by a C ABI.

A C++ application that owns the interface and the project, and a Rust core that owns the audio maths and runs WebAssembly extensions.

Extensions

Add what Audacity does not do.

An extension is a folder with two files. It receives audio blocks and can log, and nothing else.

extension.toml

The manifest: the extension's name, version, parameters and the ranges they may take.

extension.wasm

The module, built for wasm32-wasip1, exporting the entry points the host expects.

Nothing else

No filesystem, no network, no environment. If an extension fails, only that call stops — the editor and your unsaved work survive.

write one 
# an extension needs neither this tree nor a C++ compiler
rustup target add wasm32-wasip1
cp -r rust/extensions/template my-effect
# write my-effect/extension.toml and src/lib.rs
cargo build --release --target wasm32-wasip1 \
  --manifest-path my-effect/Cargo.toml
try one 
# one extension, over one WAV file, from the outside
rust/target/release/rustacity-ext-cli --describe \
  rust/extensions/dist/gain-invert
rust/target/release/rustacity-ext-cli \
  rust/extensions/dist/gain-invert in.wav out.wav \
  --param gain_db=6 --verbose

Start with rust/extensions/gain-invert — a finished extension — and read Writing an extension.

Status

Early, and honest about it.

Rustacity is under active development. Here is where things stand today.

Audio editor Recording, editing, import/export and effects — the Audacity 2.4.1 the fork is built on. Audacity 2.4.1
Rust DSP core Parts of the audio processing have moved to Rust and are checked against reference values from the original C++. In progress
Extension host Runs sandboxed WebAssembly extensions, with a deadline, a memory ceiling and no host access. Working
Editor integration Installing extensions, menu entries and parameter dialogs are still to come. Extensions are developer-facing for now. Not built yet
Prebuilt packages Produced by the release workflow when a version is tagged; otherwise build from source. On release tags

The application still reports the upstream 2.4.x version string; Rustacity releases are numbered separately (for example rustacity-0.4.0).

Build from source

Work on the Rust side without a C++ compiler.

The full application builds with CMake and needs a C++ toolchain, CMake, a Rust toolchain and the pinned wxWidgets fork. The Rust workspace is buildable on its own.

Rust toolchain C++ toolchain CMake wxWidgets · audacity-fixes-3.1.3
rust only — no C++ needed 
cd rust
# the extension host's tests build wasm fixtures:
rustup target add wasm32-wasip1
cargo test --workspace
the checks CI runs first 
# header and Rust exports must agree
python3 scripts/check_dsp_abi.py
python3 scripts/check_ext_abi.py

The per-platform recipes CI uses are the canonical build instructions: .github/workflows/cmake_build.yml. Follow the job for your operating system. A full run takes about twenty minutes.
